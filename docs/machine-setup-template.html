New machine

The order the form asks things in. Pick the protocol first. For MDB, pick the feature level next, then the plain settings; the hex payloads for that level sit behind Config, filled with the basic template. RS232 and Pulse have their own settings and the RS232 rule table sits behind its Config.

Protocol

How this machine talks to the reader. Everything below changes with this choice.

2

Feature level

What the reader declares to the machine. Ask the machine vendor if unsure. Level 3 is the safe default for new machines.

Auto sessionauto_session

On: the reader opens a session by itself after every END SESSION. Off: the app starts each session.

Not available while Always idle is on. The machine sends the vend request itself, so there is no session to open.

Auto-begin cooldownauto_begin_cooldown
auto session only

Idle POLLs the reader waits after END SESSION before it offers SESSION BEGIN again, so the machine can send its READER ENABLE first. 0 = on the very next POLL. Default 3.

idle POLLs · 0 to 50
Cancel modevmc_cancel_mode
all levels

What goes out on the next POLL after a cancelled vend. Vend Denied refuses the item and keeps the session. Session Cancel asks the machine to close the session.

Direct venddirect_vend
all levels

On: a VEND REQUEST is accepted in any state, for machines that skip the session handshake and send the request straight away. Off: only inside a session.

Nearpay UI dismissnearpay_ui_dismiss
app setting · all levels

On: the app closes the Nearpay payment screen by itself when the vend ends without a sale (machine cancel, failure, session ended). Off: the screen stays until the customer closes it. Lives in the app, not on the reader.

Always idlealways_idle
Level 3 only

On: the reader tells the machine it can take a VEND REQUEST without a session. Sets bit 5 of the last option byte, so the Expansion ID ends in 20, and turns Auto session off. Off: the byte ends in 00.

Pulse polaritypulse_mode
required

High: pulses go HIGH, the line idles LOW. Low: pulses go LOW, the line idles HIGH. Stored on the device and re-applied at every start; no pulse can be sent until it is set.

Pulse timingpulse_width_ms · pulse_period_ms

Width is the ON time of one pulse, period the time from one pulse to the next. The number of pulses comes from the sale, not from here.

What gets stored

Same keys the frontend uses today for MDB; RS232 and Pulse keys follow the same style. Settings hidden by the protocol or level are left out.


  







  

    

      
MDB COMMAND CONFIG

      
Edit the raw hex payload sent for each response — length is fixed per command, except Begin Session where the byte count is editable too (1–35 bytes). Only the commands that exist at Level 3 are shown.

      

    

    

  







  

    

      
RS232 RULE TABLE

      
One row per frame the machine can send. rx is the hex pattern to match, tx the hex reply. Price hi/lo are byte positions in the machine's frame that carry the price; amount start/end mark an ASCII amount instead (end −1 = up to the trailing CRC). First matching rule wins, top to bottom. "Event to the app" fires the same vend listener MDB uses: vend request carries the price, then exactly one success or failure per request.
