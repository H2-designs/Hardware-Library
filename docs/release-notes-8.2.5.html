Release notes - hardware-lib 8.2.5 + mqtt-lib 2.8.0

Release: https://github.com/RabbahSystems/hardware-library/releases/tag/v8.2.5 (and https://github.com/H2-designs/Hardware-Library/releases/tag/v8.2.5) Date: 25 October 2026. Replaces v8.2.4 (24 October, never cut as a GitHub release). Cumulative against the fleet's hardware-lib 8.0.0 / mqtt-lib 2.6.0.

TL;DR for the Android app

  • Swap hardware-lib-8.2.5.aar; mqtt-lib stays 2.8.0 (copy all three AARs from AAR-Update-latest.zip). Rebuild.
  • One handler change to check: every cancel now arrives as onVendFailure, and the reason says who cancelled: CANCELLED_BY_VMC (machine), CANCELLED_BY_APP (your own cancelVend(), delivered again), CANCELLED_BY_OPERATOR (new: dashboard Vend Cancel or a remote command). Branch on the reason: CANCELLED_BY_APP needs no gateway action, CANCELLED_BY_OPERATOR must void the hold (reverse if you had approved). A Java switch without default must add the new case. Full tables: CANCEL-FLOW-README.md.
  • Session-cancel retry takes the count too: setSessionCancelRetry:MS,COUNT (count 1..10, default 3). Backend keys mdb_session_cancel_retry_ms (0 = off) and mdb_session_cancel_retry_count, one number each.
  • Operator commands always answer now: [remote] reply lines such as the answer to help are no longer muted by the MQTT Logs switch.
  • Everything from 8.2.3 / 8.2.4 is included: session-cancel retry, skip 00 00 vend, RS232 leading-* patterns.

New in 8.2.5 (25 October)

Every cancel reaches onVendFailure, with a reason that says who cancelled

whohowreason
the machineVEND CANCEL 13 01, READER CANCEL 14 02, RS232 event: vendCancelCANCELLED_BY_VMC
the appcancelVend() / cancelVend(response)CANCELLED_BY_APP
an operatordashboard Vend Cancel, remote `cancelVend[:sessionCancel:vendDenied], remote setSessionMode` mid-sessionCANCELLED_BY_OPERATOR

The 8.2.2 rule that the app's own cancel was silent is withdrawn: it also hid the dashboard's cancel from the app, so an operator cancel left the payment screen open and a hold in place. One rule for the three sources is simpler. The wire replies are unchanged (VEND DENIED or SESSION CANCEL REQUEST per the cancel mode). A cancel while the session is open but before any VEND REQUEST still fires nothing, because no vend is open.

Handler rule: CANCELLED_BY_APP = you already declined, nothing at the gateway, reset the UI. CANCELLED_BY_OPERATOR = void the hold, reverse if approved, reset the UI. vendStats adds operatorCancels; vendFailuresByReason now carries all three cancel reasons. Log lines: [app] cancelVend armed ... / [operator] cancelVend armed ... followed by [mdb] vend failed: CANCELLED_BY_APP|CANCELLED_BY_OPERATOR - onVendFailure fires.

Session-cancel retry: one number for the wait, one for the count (8.2.5)

setSessionCancelRetry:MS[,COUNT] - the wait in ms (0 = off, 300..10000) and, optionally, how many re-sends before the reader gives up (1..10, default 3). Both persisted; on / off stay as aliases for 1000 / 0. SETTINGS_JSON carries sessionCancelRetryMs and sessionCancelRetryCount. Kotlin: setSessionCancelRetry(ms, maxRetries), sessionCancelRetryCount. Backend keys: mdb_session_cancel_retry_ms and mdb_session_cancel_retry_count, a plain number each.

setSessionCancelRetry:1000,3     wait 1000 ms, re-send up to 3 times (the defaults)
setSessionCancelRetry:1500,5     wait 1500 ms, up to 5 times
setSessionCancelRetry:0          off

[remote] replies are never muted

Until 8.2.4 the answers to operator commands went through the same gate as the MDB log stream, so with the Logs toggle off help, getSettings acknowledgements and the vendStats summary line were executed but never published. Now any line starting with [remote] goes out regardless. Since mqtt-lib 2.8.0 these lines travel on the ops channel, so the backend sees nothing new. If a reply is still missing, the dashboard is older than v8.2.2 and does not read ops.

Since 8.0.0 - 8.2.4 and 8.2.3 (24 October)

  • Skip 00 00 vend (setSkipZeroVend:on, default off): a VEND REQUEST priced 00 00 is ACKed and dropped.
  • Session-cancel retry (setSessionCancelRetry:on|off|MS, default off): an unanswered SESSION CANCEL REQUEST is re-sent after 1000 ms, up to 3 times (field case D-1637).
  • RS232: an rx pattern may start with * to match the end of a frame.

Since 8.0.0 - 8.2.2 / mqtt-lib 2.8.0 (22 October)

  • mqtt-lib 2.8.0: only coded items on the backend's logs topic; plain and control lines on devices/<id>/ops.
  • vendStats counters, including stuck VendListener callbacks.
  • RS232 Loyalsuns protocol v2: PRODUCTION_OK / PRODUCTION_FAIL rules ACK the making result.

Since 8.0.0 - 8.2.1, 8.2.0, 8.1.0 (October)

  • Every exchange reaches the backend exactly once (D-0961); a health check that cannot get stuck.
  • Force session end after vend (setForceSessionEnd:on|off).
  • RS232 rules fire the same VendListener; multi-input ready gate; direct vend reports ENABLED_STATE.
