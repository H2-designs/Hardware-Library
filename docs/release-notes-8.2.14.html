Release notes - hardware-lib 8.2.14 + mqtt-lib 2.8.0 + dashboard 8.2.13

Release: https://github.com/RabbahSystems/hardware-library/releases/tag/v8.2.14 (and https://github.com/H2-designs/Hardware-Library/releases/tag/v8.2.14) Date: 5 November 2026. Replaces v8.2.13 (4 November). Cumulative against the fleet's hardware-lib 8.0.0 / mqtt-lib 2.6.0.

TL;DR for the Android app

  • Swap hardware-lib-8.2.14.aar; mqtt-lib stays 2.8.0. Rebuild. No API change.
  • CASH SALE (13 05) is answered. The machine reports every cash sale (price, item) to the cashless reader so it can be logged; the reader now ACKs it in every state and logs one line. It used to be UNHANDLED (no reply), so the machine retried it a few times after every cash sale (field log 5 November: rx=13 05 00 FA 00 00 12 tx=UNHANDLED). No VendListener callback: no money moves through the reader.
  • Everything from 8.2.13 applies: warm resume, vend event gap, cancel grace, stale-approve fix, the review fixes.

New in 8.2.14 (5 November) - CASH SALE answered

frame13 05 <price hi> <price lo> <item hi> <item lo> - e.g. 13 05 00 FA 00 00 = price 250, item 0
meaninga customer paid in cash; the VMC informs the cashless reader for its audit log (spec: reader replies ACK)
beforeunhandled in every state: no reply, tx=UNHANDLED, the VMC retried the command
nowACK in INACTIVE, DISABLED, ENABLED and VEND_STATE; state unchanged; no callback
log[mdb] CASH SALE price=250 (250 minor units) item=0 - ACK (cash sale reported by the VMC, nothing to do)
exchange lineCASH SALE rx=13 05 00 FA 00 00 12 tx=ACK (CASH SALE price=250 item=0) - coded item 132 (MDB_CASH_SALE) with price and item for the backend
